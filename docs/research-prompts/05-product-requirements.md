# 5. Product Requirements (PRD Summary)

## Research Prompt

```
I need comprehensive deep research on product requirements documentation that bridges the gap between product vision and AI-assisted implementation. The goal is a generic PRD template that captures requirements in a way that directly feeds into backlog decomposition, story writing, and acceptance criteria — specifically optimized for an AI that will implement the features.

Research these specific areas:

1. **Modern PRD Approaches**
   - Amazon's "Working Backwards" — 6-pager and PR/FAQ format, when it works, limitations
   - Marty Cagan (SVPG) — product discovery, opportunity assessment, dual-track agile
   - Teresa Torres — continuous discovery habits, opportunity solution trees
   - Shape Up (Basecamp) — pitches, appetites, and fixed-time variable-scope
   - How do top product companies (Stripe, Linear, Notion) document requirements?
   - What's the minimum viable PRD that actually helps development?

2. **Requirements That AI Can Implement**
   - How to write requirements that translate directly into testable acceptance criteria
   - Jobs-to-Be-Done (JTBD) — does it produce better stories than user stories?
   - Outcome-driven requirements vs output-driven — which produces better AI implementations?
   - How to document constraints (business rules, regulatory, UX) for AI consumption
   - How specific should requirements be? Over-specification vs under-specification trade-offs
   - Writing requirements that prevent AI scope creep (clear non-goals)

3. **User Personas & User Flows**
   - Research on persona documentation that actually influences decisions
   - User flow documentation formats — when flows help vs when they're overhead
   - Edge case documentation — how to ensure AI handles error states
   - Accessibility requirements format — how to make them concrete

4. **Success Metrics & Acceptance Criteria**
   - OKRs vs KPIs — which format produces better feature definitions?
   - How to define "done" for a feature — measurable vs. subjective criteria
   - Acceptance criteria formats: Given/When/Then vs checkbox lists vs scenario tables
   - How to document "it should feel fast" (qualitative requirements → quantitative measures)

5. **PRD Structure for Iterative Development**
   - How to structure PRDs for sprint-based delivery (not waterfall)
   - Linking PRD sections to backlog epics and stories
   - How to handle PRD evolution — when requirements change mid-implementation
   - Versioning requirements documents — track decisions and changes

6. **Anti-Patterns in Requirements**
   - Requirements that are actually design solutions ("add a dropdown" vs "user can select...")
   - Ambiguous requirements that cause AI divergence
   - Missing non-functional requirements (performance, security, accessibility)
   - Over-documenting obvious capabilities while under-documenting edge cases

For each finding, include sources, examples of great PRDs, and assessment of applicability to different project sizes (solo side-project to team product).

Output a structured research report with: recommended PRD template structure, per-section content guidance, and integration points with backlog decomposition.
```
