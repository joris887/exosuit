# 5. Product Requirements (PRD Summary)

## Research Prompt

```
I need deep research on product requirements documentation that bridges the gap between product vision and AI-assisted implementation. The goal is to determine the best possible approach for a generic PRD template that captures requirements in a way that directly feeds into backlog decomposition, story writing, and acceptance criteria — specifically optimized for an AI that will implement the features.

**Framework context:** This template is part of the JD-LLM Development Framework — a language-agnostic AI development framework for Claude Code. The PRD:
- Is generated by /bootstrap Path B (new projects) from vision documents
- Feeds directly into /ideate for story decomposition
- Must bridge: product vision → backlog → stories → acceptance criteria → implementation
- Must be concise enough for efficient AI context loading during planning
The template must work for any project type (web app, API, CLI, library, mobile app).

**Research areas** (starting points — include anything significant you discover beyond these):

1. **Modern PRD Approaches** — Amazon's "Working Backwards", Marty Cagan (SVPG), Teresa Torres (continuous discovery), Shape Up (Basecamp). How do top product companies (Stripe, Linear, Notion) document requirements? What's the minimum viable PRD that actually helps development?

2. **Requirements That AI Can Implement** — How to write requirements that translate directly into testable acceptance criteria. Jobs-to-Be-Done vs user stories. Outcome-driven vs output-driven. How specific should requirements be? Preventing AI scope creep through clear non-goals.

3. **User Personas & User Flows** — Persona documentation that influences decisions. When flows help vs when they're overhead. Edge case documentation. Accessibility requirements.

4. **Success Metrics & Acceptance Criteria** — OKRs vs KPIs for feature definitions. Defining "done" measurably. Acceptance criteria formats. Quantifying qualitative requirements.

5. **PRD Structure for Iterative Development** — Sprint-based delivery structure. Linking PRD to backlog. Handling requirement changes mid-implementation.

6. **Anti-Patterns** — Requirements that are design solutions. Ambiguous requirements causing AI divergence. Missing NFRs. Over-documenting obvious things while under-documenting edge cases.

**Required output format:**
1. Executive summary
2. Per-topic findings with citations
3. **Recommended PRD template structure** — propose the specific sections, their content type, and ordering, with justification
4. **Recommended requirements format** — how individual requirements should be expressed for optimal AI implementation
5. Integration guidance — how the PRD connects to backlog decomposition
6. Knowledge gaps
```
