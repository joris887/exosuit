# 1. Architecture Documentation

## Research Prompt

```
I need you to do comprehensive deep research on architecture documentation best practices for software projects. The goal is to create the ultimate generic architecture documentation template that works for ANY project (any language, any size, any architecture style) and is specifically optimized for AI-assisted development where an AI reads this document to understand a codebase before making changes.

Research these specific areas:

1. **Documentation Models & Frameworks**
   - C4 model (Simon Brown) — all 4 levels, when to use each, what to skip for small projects
   - arc42 — template structure, which sections are essential vs optional
   - IEEE 42010 / ISO/IEC/IEEE 42010 — what's worth adopting from formal standards
   - 4+1 architectural view model (Kruchten) — which views add value for AI consumption
   - How do companies like Google, Netflix, Spotify, Stripe document their architectures?

2. **Diagrams-as-Code for Architecture**
   - Mermaid (works in GitHub markdown) — C4 diagrams, sequence diagrams, entity relationships
   - Structurizr DSL — how it extends C4 with code-level modeling
   - D2 — declarative diagramming, comparison with Mermaid
   - What diagram types actually help developers vs. what's just decoration?
   - How should diagrams be maintained to stay in sync with code?

3. **Architecture Documentation for AI Consumption**
   - What information does an AI need from architecture docs to make correct decisions?
   - How should module boundaries be described so AI respects them?
   - What's the optimal level of detail — too much wastes context, too little causes drift
   - How do you encode dependency direction in a way AI enforces?
   - How should infrastructure/deployment be documented for AI to understand environment constraints?

4. **Living Architecture Documentation**
   - How to keep architecture docs in sync with evolving code (documentation as code)
   - Architecture fitness functions — automated tests for architectural rules
   - Drift detection — how to measure when code diverges from documented architecture
   - When should ARCHITECTURE.md trigger an update? What events signal stale docs?

5. **Architecture Documentation Anti-Patterns**
   - What makes architecture docs useless? (too abstract, too detailed, never updated)
   - Common mistakes in module boundary definitions
   - Over-documenting vs under-documenting
   - Documentation that describes the ideal rather than the actual

6. **Constraints, Quality Attributes & Trade-offs**
   - How to document non-functional requirements (performance, scalability, security)
   - How to record architectural trade-offs and their rationale
   - Constraint documentation formats (budget table, SLA table, compliance matrix)

For each finding, include:
- Source URL and credibility assessment
- Specific examples or templates when available
- Whether it applies to small projects, large projects, or both
- How it benefits AI-assisted development specifically

Output a structured research report with: executive summary, per-topic findings with citations, a recommended template structure, and identified knowledge gaps.
```
