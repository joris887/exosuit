# 1. Architecture Documentation

## Research Prompt

```
I need deep research on architecture documentation best practices for software projects. The goal is to determine the best possible approach for a generic architecture documentation template — one that works for ANY project (any language, any size, any architecture style) and is specifically optimized for AI-assisted development where an AI reads this document to understand a codebase before making changes.

**Framework context:** This template is part of the JD-LLM Development Framework — a language-agnostic AI development framework for Claude Code. The template is generated by a bootstrap process that analyzes a codebase and populates it automatically. It must:
- Work for Python APIs, React apps, Go CLIs, Rust libraries, mobile apps, monorepos — anything
- Be useful to an AI making code changes (the AI reads this to understand boundaries and constraints)
- Stay under 200 lines (strict context budget — every line consumes AI context window)
- Render in GitHub markdown (so diagrams must use a markdown-native format)
- Signal when it needs updating (living documentation, not write-once)

**Research areas** (starting points — include anything significant you discover beyond these):

1. **Documentation Models & Frameworks** — C4 model, arc42, IEEE 42010, 4+1 view model, how companies like Google/Netflix/Stripe document architectures. What works, what's overhead?

2. **Diagrams-as-Code** — Mermaid, Structurizr DSL, D2, PlantUML. Which diagram types actually help developers vs decoration? How to keep diagrams in sync with code?

3. **Architecture Documentation for AI Consumption** — What information does an AI need to make correct code changes? How should module boundaries, dependency direction, and data flow be described? What's the optimal detail level (too much wastes context, too little causes drift)?

4. **Living Architecture Documentation** — Documentation-as-code, fitness functions, drift detection. When should architecture docs trigger an update?

5. **Anti-Patterns** — What makes architecture docs useless? Over-documenting vs under-documenting? Describing the ideal rather than the actual?

6. **Constraints & Quality Attributes** — How to document NFRs, trade-offs, and their rationale efficiently?

For each finding, include:
- Source URL and credibility assessment
- Whether it applies to small projects, large projects, or both
- How it benefits AI-assisted development specifically

**Required output format:**
1. Executive summary
2. Per-topic findings with citations
3. **Recommended template structure** — propose the specific sections, ordering, and format you believe is optimal for this use case, with justification for each choice
4. **Recommended diagram approach** — which tool and which diagram types, with justification
5. Identified knowledge gaps
```

```
**Instructions:**

```
