# 7. Architecture Decision Records (ADRs)

## Research Prompt

```
I need comprehensive deep research on Architecture Decision Records — how to document, govern, and leverage architectural decisions in software projects. The goal is the best possible ADR template and process that captures decisions in a way useful for both human teams and AI assistants.

Research these specific areas:

1. **ADR Formats & Evolution**
   - Michael Nygard's original ADR format — strengths and limitations
   - MADR (Markdown Any Decision Records) v4 — improvements over Nygard
   - Y-statements — "In the context of X, facing Y, we decided Z" format
   - ADR tooling — adr-tools, log4brains, adr-manager — adoption and effectiveness
   - Lightweight vs heavyweight ADRs — when each is appropriate
   - How do Google, Spotify, and ThoughtWorks use ADRs?

2. **What Makes an ADR Useful**
   - Research on ADR adoption — which teams stick with it and why?
   - What information do developers actually look for in an ADR?
   - How ADRs prevent re-litigation of past decisions
   - Decision context preservation — what's lost without ADRs?
   - ADR linking — how decisions relate to each other and to code

3. **Decision Governance**
   - Who should write ADRs? Who reviews them?
   - Status lifecycle: proposed → accepted → deprecated → superseded
   - When does a change warrant an ADR vs a commit message?
   - ADR review in PRs — how to integrate with code review
   - Compliance checking — verifying code still follows the decision

4. **ADR Anti-Patterns**
   - Decisions without alternatives explored
   - ADRs written after the fact (not capturing the actual decision process)
   - Too many ADRs (noise) vs too few (missing important context)
   - ADRs that don't connect to code (orphaned documentation)
   - Decisions that should have been ADRs but were made in Slack/meetings

5. **ADRs for AI-Assisted Development**
   - How should ADRs be structured so AI consults them during planning?
   - How to express "why NOT to do X" in a way AI respects
   - ADR + ground rules integration — when a decision becomes a permanent rule
   - Using ADRs to prevent AI from re-proposing rejected alternatives
   - ADR discovery — how AI should search for relevant decisions during story planning

6. **ADR Automation & Tooling**
   - Auto-generating ADR proposals from architectural changes
   - ADR compliance checking (ArchUnit-style)
   - ADR templates that reduce writing friction
   - ADR indices and search — making decisions discoverable

For each finding, include sources, examples of excellent ADRs, and tool comparisons.

Output a structured research report with: recommended ADR format, governance process, tooling recommendations, and integration strategy for AI-assisted workflows.
```
