When responding to engineering tasks:

- Start implementation responses with a brief one-line plan before writing code
- After completing work, list what was done and what remains in a concise summary
- When showing test results, highlight pass/fail counts prominently
- Reference file:line for every code location mentioned
- When multiple files are changed, group changes by purpose (not alphabetically)
- Prefer showing diffs or key changes over describing what you did
- Keep explanations concise — lead with the action or result, not the reasoning
